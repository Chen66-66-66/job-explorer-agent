# 样本导入

把一家公司的公告和岗位整理成一个 JSON 文件，在「公司」页点「导入样本」粘贴或选择文件，系统录入后给出导入报告。

本目录下的样本全部是虚构的。**真实招聘材料放在 `samples/private/`**（已被 `.gitignore` 排除），不要提交。

## 格式

```json
{
  "company": { "name": "公司名称（必填）", "groupName": "所属集团", "careerSiteUrl": "招聘网站", "platform": "北森" },
  "announcements": [
    { "title": "公告标题（必填）", "sourceUrl": "来源链接", "viewedAt": "2026-10-12", "content": "公告原文（必填）" }
  ],
  "positions": [
    { "title": "岗位名称（必填）", "unit": "用人单位", "location": "地点", "deadline": "2026-10-30",
      "sourceUrl": "来源链接", "viewedAt": "2026-10-12", "jdText": "岗位 JD 原文" }
  ]
}
```

- 日期一律写 `yyyy-MM-dd`。写了但无法解析时，导入报告会说明，该字段不导入。
- `viewedAt` 是查看日期。公开信息会过期，建议每条都写。

## 导入规则

- 只录入原文，不调用大模型，也不把任何东西标为已核查。条件抽取和核查仍在页面上做。
- 公司按名称合并到已有公司，只补空字段，不覆盖已填写的内容。
- 公告按标题识别：原文相同则不变；**原文不同则不覆盖**，因为公告改动会影响已抽取的公司级条件，需要人工核对。如果是新一批公告，改个标题再导入。
- 岗位按「名称 + 单位 + 地点」识别：
  - 截止日期、来源链接、查看日期有变化时更新；
  - **JD 原文有变化时，原有的确认、本人判定、材料确认和投递前核对一并失效**，规则和在页面上修改 JD 相同；
  - 样本里没写的字段不清空已有数据。
- 同一份样本重复导入，不会产生重复数据。

## 导入报告

每条公告和岗位标明结果（新增、更新、无变化、未导入），并列出缺失项：

- 没有 JD 原文、JD 中提到「详见招聘公告」「见附件」等引用材料
- 没有截止日期、截止日期已过
- 没有来源链接、未记录查看日期
- 公司没有公告时，提醒通用条件可能写在公告里
